# ControlDeck (Week 4) — Threat Model

Merges the frozen `05-week4/THREAT_MODEL.md` (12 rows), this gate's explicit security checklist, and `10-risk-register/RISK_REGISTER.md`'s priority classification into one table. Nothing here is invented — every row traces to one of those three sources.

**Baseline assumption** (`SECURITY_MODEL.md`): *"ControlDeck assumes any one model-backed agent may be compromised."* Evidence is untrusted content, not instruction. Tool output is untrusted data. Cross-agent messages are not implicitly trusted just for coming from another agent.

| # | Threat | Attack | Trust boundary | Control | Test | Priority | Residual risk |
|---|---|---|---|---|---|---|---|
| T1 | Fake multi-agent theatre | Planner output directly becomes execution | Agent → orchestrator | Typed artifacts + deterministic orchestrator + execution boundary | Attempt direct planner tool call | P0 | Shared model biases remain |
| T2 | Evidence poisoning / prompt injection | Researcher returns a document containing injected instructions ("ignore policy") | Evidence → governance | Evidence schema, source hashes, verifier classification, policy treats content as data never as control | Malicious/multilingual injection corpus (w4-003, w4-014) | P0 | Model may still be influenced semantically |
| T3 | Malicious/forged agent output | Executor claims an action already verified without a receipt | Agent → verifier | Executor cannot emit `VerificationReport`; verifier reads the receipt independently | Forged-success case (w4-004) | P0 | Verifier implementation bug |
| T4 | Agent impersonation / cross-agent output substitution | One agent's artifact is presented as another's | Agent → agent | `agent_id`, `model_id`, `prompt_version`, input/output hash recorded per model-backed step | Integration substitution test | P0 | — |
| T5 | Composition drift | Agent asks for a new tool or sub-agent | Agent → contract manifest | Contract manifest + composition attestation; forbidden-tool requests denied by name | Shadow-tool / forbidden-tool request (w4-005, w4-015, w4-023) | P0 | Supply-chain compromise outside MVP |
| T6 | Approval drift / replay | Evidence or plan changes after approval; an old approval is replayed | Human → governance | Approval bound to plan+evidence+action hashes; any change invalidates it | Mutate-after-approval case (w4-006, w4-022) | P0 | Human may approve too quickly |
| T7 | Stale/substituted evidence | A workflow advances against evidence from an old corpus snapshot | Evidence → governance | Snapshot id on every artifact; stale snapshot rejected or re-run | Snapshot-changed cases (w4-022, w4-025) | P0 | — |
| T8 | Conflicting agents | Two plans target incompatible resource versions, or two agents disagree | Agent → agent | `CONFLICT` state, resource versions, explicit human resolution — never a silent majority vote | Parallel conflict / contradictory-evidence corpus (w4-008, w4-009) | P0 | External eventual consistency |
| T9 | Retry storm / unbounded retry | Agent repeats on denial or timeout | Agent → orchestrator | Per-step budgets, circuit breaker, no retry on writes | Retry exhaustion cases (w4-010, w4-021) | P0 | Cost telemetry still needed |
| T10 | State drift / TOCTOU | Resource changes while workflow is paused or between snapshot and execution | External state → execution boundary | Fresh preconditions re-checked immediately before every state-changing action | State-drift / precondition-failed case (w4-007) | P0 | Narrow external race |
| T11 | Audit tampering | Agent (or model) edits, deletes, or forges history/events | Agent/model → ledger | Server-only append API, hash chain, integrity freeze on detected mismatch | Mutation/forged-event attempt (w4-013, w4-026) | P1 | Database administrator (or process-memory access) can still alter storage — tamper-*evident*, not tamper-proof |
| T12 | Cross-tenant deputy | Researcher/executor references or returns another tenant's evidence/resource | Principal/tenant boundary | Principal/tenant checks at every boundary, not just intake | Cross-tenant evidence case (w4-016) | P1 | Identity provider omitted from MVP |
| T13 | Credential/secret leakage | Agent output includes a secret | Agent output → context/logs | No secrets in model context ever; redaction scan on any persisted payload | Secret-shaped payload case | P1 | Host compromise |
| T14 | Unsupported/ambiguous claim | Planner or executor assumes evidence exists, or the goal itself is ambiguous | Agent → policy | Claim/evidence graph; verifier blocks `UNSUPPORTED`/`CONTRADICTED`; ambiguous goals blocked, not guessed | Missing-evidence / unsupported-claim / ambiguous-goal cases (w4-002, w4-017, w4-027) | P0 | Semantic entailment remains imperfect |
| T15 | Partial failure | One sub-effect of a multi-step action succeeds while another fails (e.g. ticket created, notification failed) | Execution boundary → verifier | Explicit `PARTIAL_FAILURE` reason code — never silently reported as full success | Partial-failure case (w4-024) | P0 | Compensation/rollback strategy is a later-gate concern |
| T16 | Unknown execution outcome | Tool call times out after a possible side effect | Execution boundary → adapter | `RECONCILIATION_REQUIRED`/`UNKNOWN_OUTCOME` state; resolved only via read-only lookup, never blind retry | Timeout-after-possible-write case (w4-011) | P0 | — |
| T17 | Direct execution bypass | Any agent attempts to reach an adapter without going through the execution boundary | Agent → adapter | Single policy-enforcement point; no agent holds adapter credentials | Bypass integration test (A2, A6) | P0 | — |
| T18 | Model-authored authoritative event | The model attempts to emit or forge a ledger event / declare workflow completion itself | Model → ledger | Events are exclusively server-constructed; a model artifact can at most be event *payload* data, never the event type/sequence/hash | Fake-completion-event case (w4-026) | P0 | — |
| T19 | Dependency confusion / supply chain | A malicious package resolves under a name ControlDeck expects internally | Package manager → build | `workspace:*` protocol for all internal cross-package deps (once the workspace exists), `"private": true` on every package, no `.npmrc` — same verified pattern as ActionHarbor's `SECURITY.md` | Manifest audit (same method as ActionHarbor Gate 11) | P1 | — |
| T20 | Time-window / scope-creep risk | Implementation exceeds the available high-capability window before Week 4 is usable | Program | Freeze specs/datasets/prompts early; strict gate discipline; stop points between gates | Program-level, not code-level | P0 | Organiser timeline still unconfirmed (§ REQUIREMENTS.md) |

## Explicit deferrals (not P0 for Gates 0-2)

- T13 (secret leakage) and T19 (dependency confusion) have no live surface until Gate 0's workspace and any real model/tool integration exist — their controls are *designed* now, verified once there is something to scan.
- T12 (cross-tenant) requires a resource/tenant model that does not exist until Gate 1's domain package.
